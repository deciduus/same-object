# Structure/tooling audit

## Summary (5 lines max)
The vault is the healthy half: `_lint.py` passes clean (91 notes, 0 errors, 0 warnings), the gap schema is genuinely atomic, and commit messages are unusually good (every one states a result, not an action).
The top-level docs are the sick half: FINDINGS.md is a pre-vault artifact still running the *retired* HOLDS/WEAKENED/WITHDRAWN vocabulary and now contradicts vault `standing` on at least six gaps.
Nothing is canonical by declaration — README, VISION, FINDINGS, 00-index and the gap frontmatter each carry their own counts, and all of them disagree (20 vs 24 vs 28 vs 49 vs 91 vs 62 vs 77).
`_idx.py` is referenced by a comment in 00-index.md and **does not exist in the repo** — the "generated" gaps block is hand-maintained, already duplicates G21, and its prose has drifted from the `note:` fields it claims to derive from.
Agent-readiness is half-built: `citation-sources.md` is a genuinely excellent runnable recipe, but there is no CLAUDE.md, no add-a-gap recipe, and no statement of which file wins on conflict — an agent landing cold will edit FINDINGS.md and make the drift worse.

## Findings

- [FINDINGS.md] HIGH — un-migrated ledger contradicting the vault on standings — six gaps carry retired verdicts (G12/G17 WITHDRAWN, G21/G22 WEAKENED, G23 HOLDS, G4 DOWNGRADED) that vault frontmatter has since reversed; 55 KB, 28 gap sections, 26 headings under "Key findings" — proposed fix: demote to `ARCHIVE-findings-2026-09.md` with a header saying "superseded by vault/00-index.md; retained for the corrections log", and move the still-live corrections log into the vault.
- [README.md] HIGH — every quantitative claim about the repo is stale — 20 vs 49 notes vs 91 actual; 62 vs 77 nodes; "four HTML files" vs six on disk — proposed fix: replace hard numbers with pointers ("see `vault/00-index.md`") or emit them from a script; add rows for `error-energy-axis.html` and `findings-synthesis.html`.
- [vault/00-index.md:124] HIGH — `<!-- generated from frontmatter by _idx.py -->` names a script that is not in the repo — `git ls-files` shows only `vault/_lint.py`; the block is hand-maintained, already contains G21 twice, and its per-gap prose differs from the `note:` field it claims to derive from — proposed fix: write `vault/_idx.py` (read frontmatter, emit the Gaps block between sentinel comments) and have `_lint.py` fail when the block differs from a fresh render.
- [vault/gaps/G4, G6, G9] HIGH — `tags:` disagree with the machine fields in the same file — G4 `evidence: full-text-read` vs tag `evidence/single-review`; G6 `citation-intersection` vs tag `full-text-read`; G9 `full-text-read` vs tag `string-protocol`; Obsidian tag-search and the frontmatter give different answers — proposed fix: add a lint rule asserting `evidence/<evidence>`, `standing/<standing>`, `crosses/<crosses>` all appear in `tags`, then fix the three files.
- [vault/_lint.py] HIGH — the BOM check never runs on the files that have BOMs — `notes()` prunes `sources/`, and all three BOM'd files (`src-2023-house-oversight-uap-hearing-transcript.md`, `src-gallaudet-2024-house-testimony.md`, `src-odni-2021-preliminary-assessment.md`) live there — proposed fix: keep sources out of the *schema* checks but run the BOM and dead-wikilink checks over them.
- [vault/_lint.py] MED — `type: source` is not in `TYPES` — the four `vault/sources/*.md` declare it and pass only because they are skipped entirely — proposed fix: add `source` to `TYPES` with a minimal required set (url, retrieved, extraction), which those files already carry in prose.
- [vault/_lint.py] MED — no `last-verified` / staleness concept — `last-checked: 2026-09-03` exists on gaps only (71 of 91 notes have no date field at all), and nothing warns when it ages — proposed fix: require `last-checked` on `gap` and `computed`, warn when older than a configurable N days (default 180).
- [vault/_lint.py] MED — no `sources` field anywhere in the schema — the project's own rule is "a figure is quotable only if the source names the fetch that produced it" (VISION.md), yet no machine field records DOIs or URLs, so no script can check it — proposed fix: add optional `sources: [doi:…, url:…]` to gap/computed/theorem and require it when `evidence: citation-intersection`.
- [vault/_lint.py] MED — edge fields are one-directional and unchecked — `computed-in` on G1 points at C8, but C8 has no frontmatter at all, so the reverse edge cannot exist and nothing verifies the forward one resolves to a `computed` note — proposed fix: require `closes`/`narrows` on computed notes and lint the pair for reciprocity.
- [vault/computed/, vault/method/, vault/moves/] MED — 25+ notes carry only `name` + `type` — C1, C2, C3, C22, all six moves and 14 method notes have no standing, no date, no edges, so `triage.base` and any future query can only see gaps — proposed fix: define a per-type minimum in `_lint.py` (computed: `closes`, `last-checked`, `result`; move: `used-by`).
- [vault/gaps/] MED — no `exit` / tombstone mechanism — G10, G13–G16, G18, G24, G26 exist in FINDINGS and are simply absent from the vault, so the reason they left is unrecoverable from the vault alone — proposed fix: add `standing: retired` plus a required `exit:` one-liner, and create 8 stub notes so the ID sequence is contiguous and auditable.
- [vault/method/citation-intersection.md] MED — hardcoded count "Eight surviving gaps have never faced this test"; actual is 12 — proposed fix: replace with a pointer to `triage.base`'s "Needs citation-intersection" view, which computes it.
- [inquiry-map.html:695-708] MED — real server-side dependency, and the data it holds is not in the repo — `await claude.use("db")` reads `collection("notes")`; per-node annotations written by the user live only in the artifact database, invisible to git, lint and Obsidian — proposed fix: either accept it as scratch (say so in README) or add a documented export step pulling the `notes` collection into `vault/` at session close.
- [README.md:38] MED — "notes persist server-side" is asserted without saying the artifact is the only copy — a reader would reasonably assume the repo is complete — proposed fix: state explicitly that map annotations are not backed up by git.
- [*.html] MED — six large hand-written documents (283 KB total) duplicating vault content with no generation link — `claims-register.html` (61 KB), `unexplored-window.html` (58 KB) and `gradient-coupling-dossier.html` (48 KB) restate gap material as inline JS data literals; nothing regenerates them, so they drift silently (the map already needed commit `b079e0a` "Correct three stale nodes in the published map") — proposed fix: keep them as published artifacts but stamp each with a `<!-- snapshot of vault @ <sha> -->` header, and long-term drive them from a generator over the frontmatter.
- [vault/.obsidian/workspace.json] MED — machine-local editor state is committed — 6.6 KB of pane layout, active-file and window geometry that changes on every Obsidian session and will conflict across machines — proposed fix: gitignore `vault/.obsidian/workspace.json` and `workspace-mobile.json`; keep `app.json`/`graph.json`/`core-plugins.json`, which are shared config.
- [repo root] MED — no CLAUDE.md, no `.claude/`, no CONTRIBUTING — an agent must infer the workflow from METHOD.md §7, which is about *briefing* agents rather than editing this repo — proposed fix: add a short CLAUDE.md naming the canonical file, the lint command, the closed vocabularies, and the "corrections stay visible" rule.
- [vault/] LOW — no add-a-gap recipe or template — `relationship-description.md` defines the six fields conceptually but nothing gives the literal 18-line frontmatter block to copy, so an agent must reverse-engineer it from an existing gap — proposed fix: add `vault/_templates/gap.md` (the `_` prefix is already excluded by lint).
- [vault/method/citation-sources.md] LOW — the best asset in the repo, and it is not discoverable as a recipe — exact endpoints, two documented endpoint traps, a verified spot-check — proposed fix: rename the section to "Recipe: run a citation intersection", add the ordered steps, and link it from CLAUDE.md.
- [vault/sources/src-2023-house-oversight-uap-hearing-transcript.md] LOW — 158 KB, 3x the next largest file, roughly 40% of the vault by bytes — a verbatim archive is defensible, but it is unreadable in Obsidian and will blow an agent's context if opened whole — proposed fix: keep verbatim, add an `## Extract index` block with line ranges for the passages actually cited elsewhere.
- [METHOD.md] LOW — 36 KB across 13 sections, half of which now exist as vault method notes — §2 co-citation audit, §11 synonym trap, §12 precedent all have counterparts (`co-citation-audit.md`, `homographs.md`, `precedent.md`) — proposed fix: reduce METHOD.md to a router, or state which is canonical section by section.
- [vault/computed/C4-inclination-sensing-limit.md] LOW — 35 KB single note; also C9 (30 KB), `vault/method/reservoir-audit.md` (28 KB) and `vault/log.md` (34 KB) — long enough that a reader cannot see the result without scrolling — proposed fix: lint warning above ~15 KB plus a required `>` result callout in the first 10 lines (most notes already have one).
- [vault/log.md] LOW — append-only operations log with no date index and no rotation, 34 KB and growing every session — proposed fix: split by month (`log/2026-09.md`) with `log.md` as an index.
- [.gitignore] LOW — covers raw media and `__pycache__` correctly but nothing else — no `.DS_Store`, no `*.tmp`, no `.obsidian/workspace*` — proposed fix: three added lines.
- [git history] LOW — no defect found; recorded as a positive — 57 commits, all dated 2026-09-03, every subject states an outcome ("Overturned. The zero was anchored on Paxos"), no wip/fix noise, no secrets or large binaries in `git ls-files` — proposed fix: none; document the convention in CLAUDE.md so agents keep it.
